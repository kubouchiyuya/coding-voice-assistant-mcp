# 初心者ガイドスキル — 技術をわかりやすく音声で伝える

プログラミング初心者や非エンジニアに向けて、技術的な概念をかみ砕いて日本語で説明するスキル。専門用語を日常的なたとえ話に置き換え、音声で読み上げることで理解を助ける。

## CLI パス

```
NOTIFY="${CLAUDE_PLUGIN_ROOT}/scripts/notify.sh"
```

## 基本方針

このスキルが発動したら、以下の手順で説明を組み立てる：

1. **まず音声で開始を宣言する**
2. **技術用語を日常語に翻訳する**
3. **たとえ話で概念を説明する**
4. **具体的なコード例を見せる（必要に応じて）**
5. **音声で要約を読み上げる**

## たとえ話辞典 — 技術用語の翻訳表

技術概念を日常に置き換える標準的なアナロジー集。これをベースに説明を構築する。

### Web・ネットワーク系
| 技術用語 | たとえ話 | 説明 |
|----------|----------|------|
| API | レストランのウェイター | お客さん（アプリ）の注文をキッチン（サーバー）に届けて料理を持ってくる |
| HTTP リクエスト | 手紙を送ること | 宛先（URL）を書いて、内容（データ）を入れて、郵便局（ブラウザ）に出す |
| JSON | 整理された注文票 | 「名前：太郎、年齢：25」のように、誰が見てもわかる書式 |
| REST API | メニュー表のあるレストラン | 決まったメニュー（エンドポイント）から注文する仕組み |
| WebSocket | 電話回線 | つなぎっぱなしでリアルタイムに会話できる |

### データ系
| 技術用語 | たとえ話 | 説明 |
|----------|----------|------|
| データベース | 整理棚・書庫 | 情報をきちんとラベルを貼って保管する場所 |

## 説明の組み立て方

### ステップ1: 開始宣言
```bash
$NOTIFY "わかりやすく説明しますね"
```

### ステップ2: たとえ話で概念を伝える
まず日常のたとえで全体像を伝える。コードは後回し。

**説明テンプレート：**
> **【一言でいうと】** {たとえ話}
>
> **【もう少し詳しく】** {日常的な言葉での説明}
>
> **【コードではこう書く】** {最小限のコード例}
>
> **【なぜ必要？】** {使わないとどうなるか}

### ステップ3: 音声で要約
```bash
$NOTIFY "{概念名}は、{たとえ話}のようなものです。{一文の要約}" complete
```

## 音声通知のルール

- 説明の**冒頭**と**まとめ**で音声を使う
- 途中の詳細説明はテキストで表示し、音声は要約のみ
- 40文字以内で区切る
- 専門用語は音声では使わない

### 実例：「APIって何？」と聞かれた場合

```bash
$NOTIFY "APIについて、わかりやすく説明しますね"
```

テキストで詳細を表示した後：

```bash
$NOTIFY "APIは、レストランのウェイターのようなものです"
$NOTIFY "アプリの注文をサーバーに届けて、結果を持ってきてくれます" complete
```

### 実例：「Gitって何？」と聞かれた場合

```bash
$NOTIFY "Gitについて説明します"
```

テキストで詳細を表示した後：

```bash
$NOTIFY "Gitは、ゲームのセーブポイントのような仕組みです"
$NOTIFY "いつでも前の状態に戻れるので、安心してコードを変更できます" complete
```

## 複合概念の説明

複数の概念が絡む場合は、ストーリー仕立てで説明する。

**例：「React のコンポーネントと Props と State」**

> レゴで家を作る場面を想像してください。
> - **コンポーネント** = レゴの各パーツ（壁、屋根、窓）
> - **Props** = 組み立て説明書。「この壁は赤色で」と親パーツから指示される
> - **State** = パーツ自身が覚えていること。窓が「開いている」か「閉まっている」か
>
> 親パーツ（家全体）が子パーツ（窓）に「赤色にして」と Props で指示。
> 窓自身は「今開いてる／閉まってる」を State で管理。

```bash
$NOTIFY "コンポーネントはレゴブロック、Propsは説明書、Stateは信号機の色です"
$NOTIFY "組み合わせて大きなアプリを作ります" complete
```

## 注意事項

- 相手の理解度に合わせて説明の深さを調整する
- 「わかった？」「大丈夫？」とは言わない。代わりに「もっと詳しく知りたいところはありますか？」と聞く
- たとえ話はあくまで入口。正確な理解が必要な場面では公式ドキュメントへの誘導も行う
- コード例は最小限にし、動作するものを見せる
